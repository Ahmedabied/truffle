# B14 The Truffle phone app (decision 0016)
Owner: opus        Wave: night of Oct 8        Due: 03:00 Oman Oct 9
Goal: the feeder becomes the Truffle app: World (WebView), Walk (Health Connect analytics in ASCII), Feed (the existing feeder), with pairing owned by the app.
Inputs: CLAUDE.md (rule 8: all Android builds on the box over `ssh workstation`, recipe in feeder-android/README.md "Build on the workstation only"), decisions/0016, 0017, feeder-android/** (all Kotlin and Gradle files, README, tests), findings/02_box_android_toolchain.md, worker/src/index.ts routes `/pair` `/feed` `/state`, worker/src/validate.ts for the phrase and secret formats, web/src/api.ts for how the web calls `/pair`.
Deliverable: code in feeder-android/, a debug APK built on the box copied to fleet/outbox/B14/raw/app-debug.apk (raw/ is gitignored) with its sha256 in RESULT.md, unit tests, RESULT.md in fleet/outbox/B14/.
Spec:
- Keep applicationId `dev.truffle.feeder`. Label "Truffle". versionName 0.2.0, versionCode 2. Plain Views, no Compose, no new heavy dependencies (a WebView and the existing libraries are enough).
- Bottom bar with three screens: World, Walk, Feed. Use one Activity and three child views or fragments, your call, but keep it small.
- Pairing: on first run with no credentials, World shows one button "make my truffle" which calls `POST /pair` on the server from settings (default the deployed origin `https://truffle.ahmed-abied.workers.dev`), stores `phrase` and `secret` in app private SharedPreferences (not backed up: check data_extraction_rules.xml), and fills the feeder's phrase automatically. Also handle the deep link `truffle://pair?creds=<phrase>.<secret>` (intent filter, scheme `truffle`, host `pair`): parse, validate formats, store, and show the World. A "forget this truffle" action under Feed.
- World screen: WebView, JavaScript on, DOM storage on, file access off, mixed content blocked, user agent = default plus the suffix ` TruffleApp/0.2`. Load `https://truffle-web.ahmed-abied.workers.dev/#creds=<phrase>.<secret>` once when credentials exist, otherwise the plain URL. Pull to refresh or a refresh action. Handle back navigation inside the WebView. External links open in the browser. The web origin is configurable in settings next to the API origin.
- Walk screen: read from Health Connect with the existing client. Today by hour (`aggregateGroupByDuration`, 1 hour buckets, steps), last 30 days by day (`aggregateGroupByPeriod`, 1 day, in the device zone), distance today (`DistanceRecord.DISTANCE_TOTAL`, only if that permission is granted; ask for it alongside steps, degrade silently if denied). Compute 7 day average, best day in 30, current streak of days at or above 3,000 steps ending today or yesterday. Render all of it as monospace text in a TextView with the Truffle colours (background #f5f2e9 / dark #141b18, ink #293e35 / #e4e9dc, accent #345437 / #7fae7a): two bar charts drawn with block characters, numbers with thousands separators, one line per stat. Put the chart text builders in a pure Kotlin object with unit tests (feed it fixed numbers, assert the lines). Steps and distance only. No calories, no weight, no heart rate, no sleep. If the Walk screen cannot read, show the permission button, same as Feed.
- Feed screen: the existing feeder UI and worker unchanged in behaviour, phrase prefilled from the app's credentials and read-only when the app owns the pet.
- Build on the box with the README recipe (rsync, gradlew assembleDebug testDebugUnitTest lintDebug). Paste the tail of the build output. If adb on the box sees a phone, do not install; Fable installs from the laptop.
Acceptance: build green on the box, unit tests green (27 existing plus the chart tests), lint has no errors, APK sha256 in RESULT.md, README updated for the app (Samsung steps stay, add the three screens and the deep link), no secret in logs or in the URL query (fragment only).
Do not: change the feed envelope or FeedProtocol behaviour, add location, add Compose, add analytics SDKs, add any body or calorie metric, build on the laptop.
Report: RESULT.md with what was done, build output tail, test output, sha256, open questions.
